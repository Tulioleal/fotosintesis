## Deferred Limitations

The following items are explicitly deferred and are not part of proposal 02:

- Time-based evidence expiry (requires a new policy version).
- Source supersession (requires a new policy version).
- Historical canonical-URL repair (historical source identities are preserved).
- Same-candidate explicit rerun endpoint.
- Existing profile section regeneration (proposal 11 boundary).
- Profile evidence fingerprints and section versions.
- Production-grade DNS pinning and peer-IP verification (the academic contract uses basic HTTPS, approved-hostname, redirect, timeout, content-type, and bounded-body gates).
- Runtime adoption or merge of ambiguous null-key legacy profiles: only the 0014 migration backfills unambiguous controlled legacy rows, and ambiguous rows stay unchanged (controlled development/test databases may be recreated).

## Hardening status

The following hardening items from the `harden-confirmed-plant-enrichment` change are implemented in this proposal and covered by the executable tests referenced above:

- Judge-only coverage never turns an exhausted job into `partial`; durable accepted progress is authoritative.
- Terminal efficacy telemetry and operational limitations (`retry_exhausted`, `workflow_incomplete`, `indexing_deferred`) are derived from the durable checkpoint with enqueue-to-terminal duration.
- Per-aspect local retrieval requires validation provenance for the requested aspect and preserves coverage-balanced ordering through the judge budget.
- Confirmed enrichment persists only successfully fetched trusted content (snippet-only failures have zero domain and vector effects).
- Server-resolved confirmed candidate identity is authoritative over garden display matching and never trusts client taxonomy keys.
- New canonical profile snapshots are built only from accepted evidence (proven by `tests/integration/test_enrichment_aspect_convergence.py::test_new_profile_snapshot_includes_only_accepted_canonical_evidence` with independent gates for mismatched aspect validation, legacy null-key fallback, untrusted source, rejected review state, missing support, and missing validation), concurrent creation converges on one profile (`tests/integration/test_profile_concurrent_creation.py::test_real_concurrent_profile_creation_converges_on_one_row`), and existing snapshots are never regenerated.
- Frontend enrichment polling uses a bounded candidate-and-job-scoped client observation window with an accessible manual refresh.

Do not use checked archived tasks as the only acceptance evidence for any row above; every row points to executable test names under `backend/tests` or `frontend`.
